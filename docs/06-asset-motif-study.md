# 素材の適性評価とモチーフ設計

提供素材: `~/Downloads/SVG/アセット 1.svg`（624 KB / viewBox 247.09 × 320.36）

---

## 1. 結論: **この SVG をそのまま渡すことはできない**

理由は 1 つ。**ファイルの 95.3% が埋め込みラスタ画像で、`SVGLoader` はそれを読まない。**

### 実体の内訳

| 中身 | 実体 |
|---|---|
| 埋め込み PNG × 2（base64） | **580 KB / 全体の 95.3%** ← 絵のほぼすべて |
| ベクター図形 | 29 KB のみ（`rect` 72 / `path` 43 / `polygon` 18 / `polyline` 8 / `line` 8） |
| `<clipPath>` | **41 個** |
| グラデーション / パターン | 8 / 2 |
| `<text>`（GothicBBBPr6N, KozGoPr6N） | 2 |

埋め込み PNG の正体:
- `image[1]` 1026 × 1457 — **キャラクターイラスト**（版面のほぼ全面を占める）
- `image[0]` 316 × 180 — **「ミステ!?キス / Mystery Kiss」ロゴ**

つまりこれは**キャラクター設定資料（版面）を SVG でラップしたもの**であって、ベクター素材ではありません。

### 渡すとどうなるか

`GlassObject` / `ParticleObject` の SVG 経路はこうなっています:

```ts
function shapesFromSvg(text: string): THREE.Shape[] {
  const parsed = new SVGLoader().parse(text);
  for (const path of parsed.paths) {
    if (style?.fill === "none") continue;      // 線だけの図形は捨てる
    shapes.push(...SVGLoader.createShapes(path));
  }
  if (shapes.length === 0) throw new Error("No fillable shapes in the SVG");
}
```

three.js の `SVGLoader` が解釈するのは `path/rect/polygon/polyline/circle/ellipse/line/g/use` のみ。
**`<image>` と `<text>` は解釈対象外**です。さらに:

- `<image>` 無視 → **キャラクターもロゴも消える**
- `<text>` 無視 → 2 つの注記ラベルも消える（フォントのラスタライズは行われない）
- `<clipPath>` 41 個 無視 → クリップされているはずの図形が全面表示される
- グラデーション / パターン（`fill: url(#…)`）未解決
- `fill: none` の細線（0.3〜0.5px）は上記のとおり除外される

**結果として残るのは、設定資料の枠線・罫線・矩形だけ。** それがガラスに押し出されます。狙った絵にはなりません。

## 2. ただし中身の PNG は優秀。**そちらを使ってください**

抽出してアルファを調べたところ、2 枚とも**きれいな切り抜き済み RGBA**でした。

| 画像 | 寸法 | 完全透過 | 完全不透明 | 評価 |
|---|---|---|---|---|
| キャラクター | 1026 × 1457 | **80.0%** | 19.5% | 切り抜き良好・輪郭明確 |
| ロゴ | 316 × 180 | 49.9% | 36.5% | 切り抜き良好 |

`app/public/images/` に取り出して配置済みです:

## 3. 決定的な違い: 3 種は同じ画像を渡しても**処理がまったく別**

ソースを読んで判明した、ドキュメントに書かれていない挙動です。**モチーフ選定はここで決まります。**

### GlassObject → **アルファのシルエットだけ抽出。中身の色は捨てられる**
```ts
mask[i] = data.data[i * 4 + 3] >= ALPHA_THRESHOLD ? 1 : 0;   // α だけ見る
loops = traceContours(mask, width, height);                   // 輪郭をトレース
new THREE.ExtrudeGeometry(shapes, {...});                     // 押し出してガラス化
```
→ 画像を渡すと**「輪郭の形をしたガラスの塊」**になります。顔も服の色も残りません。
（内側の穴は `holes` として正しく処理されるので、ドーナツ状の抜きは活きます）

### ParticleObject → **ピクセルの RGB を保持する**
```ts
data.data[i] / 255, data.data[i+1] / 255, data.data[i+2] / 255   // 色を粒子に載せる
```
→ **イラストが色そのままで粒子群になります。** キャラクターイラストに最適。

### DitheredObject → **GLB / glTF のみ。画像も SVG も不可**
1bit ベイヤーディザなので**色は意味を持たず、形と陰影だけ**が見えます。

## 4. モチーフ適性表

| | GlassObject | ParticleObject | DitheredObject |
|---|---|---|---|
| 入力 | GLB / SVG / 画像 | GLB / SVG / 画像 | **GLB / glTF のみ** |
| 効くもの | **輪郭** | **色 + 形** | **立体の陰影** |
| 適したモチーフ | ロゴマーク、1 文字の漢字・かな、幾何記号、鍵・星・雫など単純な物体 | 色鮮やかなキャラ・イラスト、写真的な被写体 | 球・トーラス・胸像・製品形状など、曲面のあるもの |
| 避けるもの | 細線、繊細な突起、文字数の多い版面、写実イラスト | 低コントラスト、背景不透過、巨大すぎる画像 | 平板なもの、テクスチャ頼みのもの |
| 手持ち素材 | ロゴ △（後述） | **キャラ ◎ 最適** | **なし ❌ 要調達** |

### 手持ち素材の当てはめ

- **`ParticleObject` ← `character-sm.png`** … ◎ そのまま使えます。**最良の組み合わせ**
- **`GlassObject` ← `logo.png`** … △ 動きますが、PNG からの輪郭トレースなので
  ロゴの文字が 1 つの塊に潰れ、可読性が落ちます。
  → **ロゴをアウトライン化した純ベクター SVG**（`<image>` を含まないもの）があれば ◎ になります。
  Illustrator から「テキストをアウトライン化 → 画像を埋め込まず SVG 書き出し」で作れます
- **`DitheredObject`** … ❌ **GLB がありません。ここが唯一の実質的な欠落です**

## 5. 見落としがちな用途: **Wrapper 22 種の「被写体」にもなる**

Wrapper 系は DOM をそのままキャプチャします。つまり `<img src="/images/character.png">` を
中に置けば、**キャラクターが 22 種すべてのエフェクトの被写体になります**。

```tsx
<Shatter>
  <img src="/images/character.png" alt="" />   {/* ガラス片になって浮き上がる */}
</Shatter>
```

→ **1 枚のイラストが、ParticleObject と合わせて 23 箇所で使い回せます。** 調達コストの観点で非常に効率が良い。

## 6. モチーフ選定の指針 — 「何を被写体にするか」

### 原則: **抽象モチーフはエフェクトの評価を難しくする**

幾何学模様やグラデーションを被写体にすると、
**どこまでが元の絵で、どこからがエフェクトなのか**が見分けられません。
一方、**見慣れた具体物**（キャラクター・製品・文字）を被写体にすると、
「本来こう見えるはず」という基準が観客の頭にあるため、**歪みや崩れが正しく伝わります**。

→ **デモ LP においてキャラクター IP を主役に据えるのは、記憶に残るだけでなく機能的にも正しい選択です。**

### エフェクト種別ごとに映える題材

| エフェクト種別 | 映える題材 | 理由 |
|---|---|---|
| レンズ系（`Glass` `Magnify` `RetroDither` `Asciify`） | **情報密度の高い版面** — 仕様表、細かい注記、地図、設定資料 | 「覗き込んで読む」動機が生まれる。`targets` でズームさせる対象も作れる |
| 破壊系（`VHS` `Glitch`） | レトロな題材、太い見出し、人物 | 顔が歪むと壊れ方が伝わる。細い本文は消えるので不可 |
| 流体系（`Liquid` `Ripple` `Droplets` `Frost`） | 彩度の高い面、写真・イラスト | 屈折は色の差があるほど見える。単色背景では効果が見えない |
| ジオメトリ系（`Shatter` `Grid` `HexFloat` `Peel`） | 大きな色面を持つイラスト | タイル 1 枚ごとに違う色が乗ると分割が伝わる |
| パーティクル系（`ParticleReveal` `ParticleScroll`） | 高コントラストな被写体 | `ParticleReveal` は背景色との差で UI ピクセルを判定するため |
| アンビエント（`Blaze` `Clouds`） | 何でも可 | 上に重なるだけなので被写体を選ばない |

**元の設定資料（版面全体）は、実は捨てるには惜しい素材です。**
ラスタライズして `<img>` として置けば、**レンズ系セクションの理想的な被写体**になります
（細かい注記を `Magnify` で走査する画は説得力があります）。

## 7. 必要な素材の全体像

| | 種別 | 用途 | 状況 |
|---|---|---|---|
| **A** | 色付きイラスト（透過 PNG） | `ParticleObject` + Wrapper 22 種の被写体 | ✅ **入手済み** `character.png` |
| **B** | シルエット用ベクターマーク | `GlassObject` | △ ロゴ PNG で代用可。**純 SVG 版が望ましい** |
| **C** | **GLB / glTF モデル** | `DitheredObject` | ❌ **未入手。唯一の欠落** |
| **D** | HTML コンテンツ（コピー・UI） | Wrapper 22 種 | 未着手（LP のコピー設計と一体） |
| **E** | `Peel` の第 2 レイヤー | `Peel` | 未定 |
| **F** | 高密度な版面画像 | レンズ系の被写体 | ✅ 設定資料をラスタライズすれば流用可 |

### C（GLB）の調達方針

1. **キャラクターを 3D 化** — 世界観は最も揃うが、コストが高い
2. **既存の CC0 モデルを使う** — Poly Haven / Khronos glTF Sample Models。低コスト・確実
3. **単純な幾何立体を自作** — Blender で球やトーラスノット。**1bit ディザは曲面の階調が主役なので、
   実はこれで十分成立します。** コスト最小で推奨

> `DitheredObject` は色を捨てるため、モデルの作り込みが効きにくい部分です。
> ここに時間をかけるより、**曲面のある単純な形**で済ませて他に注力するのが合理的です。
