## 1. 背景と目的

### 1.1 背景
[canvasui.dev](https://canvasui.dev) は html-in-canvas と WebGL による
**25 種のビジュアルエフェクトコンポーネント**を提供する OSS ライブラリ。
ライブラリの全機能を体系的に見せ、かつ**組み合わせたときに何が起きるかを検証した資料**は
公式にも存在しない。

### 1.2 目的
1. **全 25 機能を、実際に動く形で網羅的に紹介する**
2. **組み合わせ利用の可能性と限界を、検証にもとづいて提示する**（本 LP の主題）
3. 上記を、**技術的制約の中で破綻させずに**成立させる

### 1.3 成功の定義
- 訪問者が 25 機能すべてを実際に体験できる（対応環境において）
- 「どの組み合わせが成立し、どれが破綻するか」が根拠つきで示されている
- 非対応環境の訪問者も、**内容をすべて読める**
- 一度もクラッシュ・黒画面・フリーズを起こさない

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| **Wrapper 系** | `children` を包み、ページの実 DOM をキャプチャして加工するコンポーネント。**22 種** |
| **Object 系** | `src` で外部アセットを受け取り three.js で描画するコンポーネント。**3 種**（`GlassObject` / `ParticleObject` / `DitheredObject`） |
| **html-in-canvas** | `ctx.drawElementImage()` / `canvas.requestPaint()` / `layoutsubtree` 属性からなる Chrome の実験的 API |
| **対応環境** | html-in-canvas が利用可能なブラウザ（Origin Trial 有効な Chrome 148〜150、またはフラグ有効環境） |
| **非対応環境** | 上記以外。Wrapper 系 22 種が素の HTML にフォールバックする |
| **コンテキスト予算** | 同時に保持してよい WebGL コンテキスト数の上限。超過するとブラウザが古いものを破棄する |
| **マウント** | コンポーネントが DOM に存在し WebGL コンテキストを保持している状態 |
| **アンマウント** | DOM から除去され `destroy()` によりコンテキストが解放された状態 |
| **フォールバック** | エフェクトを適用せず、素の HTML として内容を表示すること |
| **効果セクション** | エフェクトコンポーネントを含む LP のセクション |

## 3. スコープ

### 3.1 対象に含むもの
- 25 コンポーネントすべての紹介セクション
- 組み合わせの実演と、検証結果にもとづく相性の提示
- レンダリング資源（コンテキスト予算）の管理機構
- 非対応環境向けフォールバックと告知
- 導入方法（CLI / MCP）の案内
- 組み合わせ検証を行うための実験ページ

### 3.2 対象に含まないもの
| 除外項目 | 理由 |
|---|---|
| Canvas UI 本体の改修・PR | 本 LP は利用側。ソースは参照のみ |
| 各エフェクトの録画動画・静止画による代替表示 | 「自動フォールバック＋告知バナー」方針を採用（§6.2） |
| React 以外のフレームワーク版の実装 | スタックを React 19 + Vite + TS に確定済み |
| 多言語対応 | 日本語のみ |
| CMS・管理画面 | 静的サイト |
| ユーザー認証・サーバーへのデータ送信 | 静的サイト。アップロード機能（REQ-11）もブラウザ内処理のみ |
| アップロード結果の共有・公開・保存 | **意図的に持たない**（REQ-11.13）。公開機能を持つと投稿プラットフォームとなり、権利・モデレーションの責務が発生するため |
| **Firefox での動作検証** | **2026-07-26 に対象外と決定**（ご担当者判断）。フォールバックは機能検出（`drawElementImage` の有無）で分岐する**ブラウザ非依存の仕組み**であり、同じく非対応の Safari 26.3 で合格済み。Firefox も同挙動になる見込みだが**未検証**である点は明示する |

### 3.3 段階的リリース
| 段階 | 内容 | 位置づけ |
|---|---|---|
| **M0** | 検証ページ（§7.10） | 必須。M1 の前提 |
| **M1** | 全 25 機能のカタログ + 資源管理 + フォールバック | **MVP** |
| **M2** | 組み合わせラボ + 相性マトリクス | 主題。MVP 直後 |
| **M3** | 導入案内・SEO・仕上げ | 任意 |
| **M4** | **素材アップロード・プレイグラウンド**（REQ-11） | **将来対応。MVP では実装しない** |

> **M4 について**: MVP では実装しないが、**後から追加できる構造を M1 の時点で確保する**（`design.md` §15.5）。
> 具体的には素材参照の抽象化のみ。これを怠ると M4 で 3 セクションの作り直しが発生する。

## 5. 前提条件と依存

### 5.1 前提
- スタックは **React 19 + Vite + TypeScript**（確定済み）
- コンポーネントは shadcn レジストリ経由で**ソースがリポジトリに取り込まれる**（npm 依存ではない）
- Wrapper 系 22 種は **npm 依存ゼロ**。Object 系 3 種のみ `three` / `@types/three` を要する

### 5.2 外部依存
| 依存 | 内容 | リスク |
|---|---|---|
| Chrome Origin Trial | HTML-in-Canvas（Chrome 154 まで） | **取得済み（2026-07-26）。失効 2026-10-20。失効すると全 22 種がフォールバックする** |
| `canvasui.dev` レジストリ | コンポーネント取得元 | 取得は初回のみ。以後はローカルソース |
| `three` / `@types/three` | Object 系 3 種 | 通常の npm 依存 |
| Draco デコーダ（gstatic CDN） | Draco 圧縮 GLB 使用時のみ | 自前ホストで回避可 |
| 3D / 画像アセット | 別途調達中 | **未確定。§7.7 参照** |

### 5.3 ライセンス
Canvas UI は **MIT + Commons Clause**。個人・商用利用は可。
本 LP は利用側であり、ライブラリ本体の販売は行わないため抵触しない。

## 6. 制約

制約は要件を規定する。**以下は交渉不可の技術的事実**であり、設計はこれに従う。

### 6.1 【最重要】WebGL コンテキスト予算
- 1 コンポーネント = **1 WebGL コンテキスト**（Wrapper 系 22 / Object 系 3 とも）
- ブラウザの同時保持上限は概ね **16**。超過すると古いものから強制破棄される
- **全 25 コンポーネントに `webglcontextlost` ハンドラが存在しない（0/25）**
  → 一度失われたら**復帰しない**（黒画面のまま）
- 各コンポーネント内蔵の `IntersectionObserver` は **rAF を止めるだけでコンテキストを解放しない**
  → **スクロールしても予算は減らない**
- `destroy()` は 25/25 で完備 → **アンマウントによってのみ解放できる**

**帰結: 25 機能を常時マウントする実装は成立しない。資源管理は機能要件である（§7.4）。**

### 6.2 ブラウザ対応
- Wrapper 系 22 種は **Chrome 専用**（Origin Trial 148〜150。Firefox / Safari は実装表明なし）
- Object 系 3 種は three.js のみに依存 → **全モダンブラウザで動作**
- 非対応環境では各コンポーネントが**自動的に素の HTML を描画**する（エラーは発生しない）

### 6.3 コンポーネント仕様に起因する制約
| 制約 | 内容 |
|---|---|
| 色指定 | Wrapper 系の色は **`[r, g, b]` の 0〜1 正規化値**（0〜255 ではない）。Object 系のみ CSS 文字列 |
| `"auto"` 背景 | ページ背景をサンプリングする。**入れ子では破綻の可能性**（要検証 T-5） |
| Object 系の 2D 画像入力 | `GlassObject` は**アルファのシルエットのみ**抽出し色を捨てる。`ParticleObject` は **RGB を保持**する |
| `DitheredObject` | **GLB / glTF のみ**。画像・SVG 不可 |
| スクロール駆動型 | `Laser` / `ParticleScroll` / `Bend` はスクロール量でコンテンツの見え方を占有する |
| `Peel` | めくった下に見せる**第 2 レイヤーの内容**が別途必要 |
| **タッチ環境の制約** | **25 種中 17 種**がポインタ依存。タッチにはホバーが無く、`touch-action` 未指定のためスクロールに奪われる。**モバイルでは本来の見え方にならない**。ベンダー改変なしには直せないため、**LP 側で事実を提示する方針**（2026-07-26 / `docs/01` §4）。判定はソース走査で自動生成 |
| **解像度の非対称** | Wrapper 系はソースを 1x、出力を DPR 倍で描く。**Retina ではエフェクト越しの文字が実質半分の解像度**になり甘く見える。ベンダー改変なしには直せないため**現状維持と決定**（2026-07-26 / `docs/01` §4）。被写体の文字を大きく保つ指針（`ui-design.md` §3.2）が緩和策になっている |

記法: **WHEN**（事象駆動） / **WHILE**（状態駆動） / **IF**（異常系） / **WHERE**（条件付き） / 無印（常時）

### 7.1 REQ-1: コンポーネントカタログ

> **ユーザーストーリー**
> P1 として、25 種すべてのエフェクトを実際に動く状態で確認したい。
> 導入を検討するために、各機能が何をするものかを一目で把握したいからだ。

| # | 受入基準 |
|---|---|
| 1.1 | LP は **25 コンポーネントすべて**の紹介セクションを含むこと |
| 1.2 | 各セクションは、コンポーネント名・機能の説明・**実際に動作するデモ**を含むこと |
| 1.3 | 各セクションは、そのコンポーネントの**導入コマンド**（`npx shadcn@latest add @canvas-ui/<name>-react`）を表示すること |
| 1.4 | **WHEN** 効果セクションがビューポートに入ったとき、システムはそのエフェクトの描画を開始すること |
| 1.5 | 各デモは、そのエフェクトの**特徴が判別できる被写体**を用いること（§7.9 のモチーフ指針に従う） |
| 1.6 | スクロール駆動型 3 種（`Laser` / `ParticleScroll` / `Bend`）は、**それぞれ独立したセクション**に配置すること |
| 1.7 | カタログはカテゴリ順に並べ、**同一カテゴリが 3 つ以上連続しない**こと |

### 7.2 REQ-2: 組み合わせラボ

> **ユーザーストーリー**
> P1 として、複数のエフェクトを組み合わせたときに何が起きるかを知りたい。
> 自分のプロダクトで重ねて使えるかを判断したいからだ。

| # | 受入基準 |
|---|---|
| 2.1 | LP は、**単一コンポーネントのオプション操作**で複合表現を作れることを示すセクションを含むこと（例: `Glass` に `blur`＋`aberration`＋`zoom` を同時適用） |
| 2.2 | 2.1 のセクションは、訪問者が**オプション値を実際に操作できる** UI を提供すること |
| 2.3 | LP は、組み合わせの実演を含むこと。**検証 T-2 により Wrapper どうしの入れ子は不成立と判明したため、REQ-10.6 に従い「並置による提示」と読み替える**（最低 2 例） |
| 2.4 | **WHILE** 組み合わせ実演が表示されている間、システムは同時に **1 組（最大 2 コンポーネント）のみ**をマウントすること |
| 2.5 | **WHEN** 訪問者が組み合わせを切り替えたとき、システムは切り替え前の組をアンマウントしてから新しい組をマウントすること |
| 2.6 | LP は、**破綻する組み合わせ**を「避けるべき例」として明示的に提示すること（レンズ型どうし、ジオメトリ変形どうし 等） |
| ~~2.7~~ | ~~入れ子の深さは 2 段以下~~ → **失効**。T-2 不成立により入れ子自体を使わない |
| 2.8 | **WHERE** 検証 T-3（Object 系を Wrapper に内包）が成立した場合に限り、その実演を含めてよい。→ **T-3 成立を確認済み。実演を含める**（成立する唯一の重ね合わせ） |
| 2.9 | 組み合わせで使用する色指定は `"auto"` を用いず、**RGB を明示指定**すること |

### 7.3 REQ-3: 相性マトリクス

> **ユーザーストーリー**
> P1 として、どの組み合わせが安全でどれが危険かを一覧で把握したい。
> 個別に試さずに判断したいからだ。

| # | 受入基準 |
|---|---|

| 3.3 | マトリクスの内容は、**検証（§7.10）の実測結果にもとづく**こと。推測のみの記載を含めないこと |
| 3.4 | LP は、コンテキスト予算の制約とその帰結を説明するセクションを含むこと |
| 3.5 | LP は、ブラウザ対応状況（Chrome 限定・Origin Trial・他エンジン未対応）を明示するセクションを含むこと |

### 7.4 REQ-4: レンダリング資源管理【最重要】

> **ユーザーストーリー**
> P1 / P2 として、LP を最後までスクロールしても表示が壊れないでほしい。
> 途中で黒画面になったら内容が読めないからだ。

**§6.1 の制約に対応する、本 LP の中核要件。**

| # | 受入基準 |
|---|---|
| 4.1 | システムは、同時にマウントする効果コンポーネント数を **設定可能な上限値以下**に保つこと |
| 4.2 | 上限値の初期値は **8** とし、検証 T-6 の実測結果により確定すること |
| 4.3 | **WHEN** 効果セクションがビューポートから設定距離以上離れたとき、システムはそのコンポーネントを**アンマウントし WebGL コンテキストを解放**すること |
| 4.4 | **WHEN** アンマウント済みのセクションが再びビューポートに近づいたとき、システムはそのコンポーネントを**再マウントし、正常に描画を再開**すること |
| 4.5 | **WHILE** LP 全体をスクロールしている間、保持される WebGL コンテキスト数は 4.1 の上限を超えないこと |
| 4.6 | システムは、LP を**上から下まで、および下から上まで**通しでスクロールしても、いずれのセクションも黒画面・描画停止に陥らないこと |
| 4.7 | **IF** WebGL コンテキストの生成に失敗した場合、システムは当該セクションを**フォールバック表示**に切り替え、他セクションに影響を与えないこと |
| 4.8 | アンマウント時、システムは対象コンポーネントの `destroy()` を呼び出すこと |
| 4.9 | 資源管理機構は、25 セクションすべてに**共通の仕組みとして**適用されること（セクションごとの個別実装を禁ずる） |

### 7.5 REQ-5: ブラウザ対応とフォールバック

> **ユーザーストーリー**
> P2 として、Safari で開いても内容を読みたい。
> エフェクトが見えなくても、このライブラリが何なのかは知りたいからだ。

| # | 受入基準 |
|---|---|
| 5.1 | **IF** 実行環境が html-in-canvas に非対応の場合、システムは全セクションの**内容を素の HTML として表示**すること |
| 5.2 | 5.1 の状態で、システムはエラー・警告・空白領域を発生させないこと |
| 5.3 | **IF** 実行環境が非対応の場合、システムは**告知バナー**を表示し、対応環境（Chrome）で閲覧すると全機能を体験できる旨を伝えること |
| 5.4 | 告知バナーは、訪問者が**閉じられる**こと。閉じた状態はセッション内で保持されること |
| 5.5 | 告知バナーはコンテンツを覆い隠さないこと |
| 5.6 | **WHERE** 環境が対応している場合、告知バナーを表示しないこと |
| 5.7 | Object 系 3 種のセクションは、**非対応環境でも通常どおり動作**すること（three.js のみに依存するため） |
| 5.8 | 対応判定は `ctx.drawElementImage` と `canvas.requestPaint` の存在によって行うこと |
| 5.9 | **IF** Origin Trial トークンが未設定または失効している場合も、5.1〜5.3 と同じ挙動となること |

### 7.6 REQ-6: アクセシビリティ

> **ユーザーストーリー**
> P3 として、過剰な動きなしに内容を読みたい。
> 動きの多い画面では体調を崩すからだ。

| # | 受入基準 |
|---|---|
| 6.1 | **IF** `prefers-reduced-motion: reduce` が設定されている場合、全 25 セクションでモーションが抑制されること |
| 6.2 | 6.1 の状態でも、システムは**すべての内容を読める形で表示**すること |
| 6.3 | すべての本文テキストは、**DOM 上に実テキストとして存在**すること（画像化・canvas 描画のみでの提供を禁ずる） |
| 6.4 | エフェクトの出力キャンバスは `aria-hidden` かつ `pointer-events: none` であり、支援技術に露出しないこと |
| 6.5 | LP は**キーボードのみで全セクションを走査**できること |
| 6.6 | 本文テキストのコントラスト比は **WCAG 2.1 AA（4.5:1）以上**であること。**エフェクト非適用状態で判定**する |
| 6.7 | 破壊系エフェクト（`Glitch` / `VHS` / `RetroDither` / `ParticleReveal`）は、**本文には最大 1 段まで**とし、可読性を損なわないこと |
| 6.8 | すべての `<img>` に適切な `alt` を付与すること。装飾目的の場合は空 `alt` とすること |

### 7.7 REQ-7: 3D / 画像アセット

> **ユーザーストーリー**
> P5 として、Object 系 3 種を素材の差し替えだけで運用したい。
> 素材は後から用意・変更されるからだ。

| # | 受入基準 |
|---|---|
| 7.1 | システムは `GlassObject` / `ParticleObject` / `DitheredObject` の 3 セクションを含むこと |
| 7.2 | 各アセットの参照パスは**一箇所で定義**され、差し替え時にセクション実装を変更せずに済むこと |
| 7.3 | **IF** アセットの読み込みに失敗した場合、システムは `onError` を捕捉し、**代替表示に切り替えて他セクションに影響を与えない**こと |

### 7.11 REQ-11: 素材アップロード・プレイグラウンド【M4 / MVP 対象外】

> **ユーザーストーリー**
> P1 として、自分の素材を持ち込んでその場で効果を確認したい。
> 導入前に、自社のロゴやモデルで実際にどう見えるかを確かめたいからだ。

**MVP では実装しない。** ただし本節を要件として確定させ、M1 の設計に後方互換の余地を残す。

#### 実現可能性（確認済み）
Canvas UI の Object 系 3 種は、**この用途を公式に想定している**。
`src` オプションの説明に次の記載がある（3 種すべて）:

> "Object URLs from a file input work too. The format is sniffed from the bytes, not the extension."

実装も `fetch(src)` → `arrayBuffer()` → **マジックバイトによる形式判定**という経路で、
Object URL（`blob:`）をそのまま受け付ける。拡張子の偽装や欠落があっても正しく判定される。
`onLoad` / `onError` も備わっており、異常系を扱える。→ **実現可能**。

| # | 受入基準 |
|---|---|
| 11.1 | 訪問者がローカルファイルを選択できること（ファイル選択ダイアログおよびドラッグ&ドロップ） |
| 11.2 | 選択されたファイルは**ブラウザ内でのみ処理**し、いかなるサーバーへも送信しないこと（NFR-4.2） |
| 11.3 | 選択された素材を Object 系 3 種に適用し、その場で描画すること |
| 11.4 | **WHERE** 実行環境が対応環境であり、かつ素材が画像の場合、Wrapper 系エフェクトの**被写体**としても適用できること |
| 11.5 | **IF** 実行環境が非対応環境の場合でも、Object 系 3 種のプレイグラウンドは**通常どおり動作**すること |
| 11.6 | **IF** 対応外の形式が選択された場合、システムは受理せず、対応形式を提示すること |
| 11.7 | **IF** ファイルサイズまたは画像解像度が上限を超える場合、システムは受理を拒否するか、自動的に縮小して処理すること |
| 11.8 | **IF** 素材の読み込み・解析に失敗した場合、システムは `onError` を捕捉し、**原因を訪問者に提示**して直前の状態を維持すること |
| 11.9 | システムが同時に保持するアップロード素材は **1 件**とし、差し替え時に前の Object URL を解放すること |
| 11.10 | アップロードされた素材を永続化しないこと。ページを再読み込みすると破棄されること |
| 11.11 | **WHILE** プレイグラウンドが表示されている間、同時にマウントするエフェクトは **1 つのみ**とすること（REQ-4 の予算内で動作すること） |
| 11.12 | **WHEN** 訪問者がエフェクトを切り替えたとき、システムはアップロード素材を保持したままエフェクトのみを差し替えること |
| 11.13 | アップロードされた素材および描画結果を、**外部へ共有・公開・保存する機能を持たない**こと |
| 11.14 | 訪問者に対し、ファイルが端末外へ送信されないことを明示すること |

#### 既知の制約（設計・実装時に遵守）
| 制約 | 内容 | 根拠 |
|---|---|---|
| **GLB のみ** | 外部 `.bin` / テクスチャを参照する `.gltf` は不可。Object URL には基準ディレクトリが無いため相対参照が解決できない | 読み込みが `fetch` → `arrayBuffer` → マジックバイト判定のため |
| **結果画像の書き出し不可** | 「描画結果をダウンロード」は実現できない | 全コンポーネントが `preserveDrawingBuffer` を設定しておらず、canvas 読み出しが空になる。回避には本体改変が必要（NFR-3.2 に抵触） |
| **SVG を DOM に挿入しない** | アップロード SVG は必ず `SVGLoader` の解析対象としてのみ扱う | 未検証の外部 SVG を DOM へ挿入するとスクリプト実行の恐れがあるため |
| **`DitheredObject` は GLB のみ** | 画像・SVG を渡せない | §6.3 |
| **巨大画像の負荷** | `ParticleObject` は画素から粒子を生成するため、高解像度画像は破綻する | REQ-11.7 で上限を設ける |
