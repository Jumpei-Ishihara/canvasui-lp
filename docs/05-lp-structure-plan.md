## 3. [04] 組み合わせラボ — 研究パート

### 4-1. パラメータ融合（P6）— リスク最小で見せ場になる
`Glass` 1 つに `blur` + `aberration` + `zoom` + `targets` を同時適用し、
**「重ねなくてもここまでできる」**を示す。スライダーで 409 options の一部を実操作させる。
→ **WebGL コンテキストは 1 つしか使わない**のに情報量が多い。費用対効果が最も高い。

### 4-2. アンビエント × レンズ（6-A）— 入れ子 2 段の実演
```tsx
<VHS>
  <Glass>…</Glass>
</VHS>
```
候補 4 つ（`VHS`×`Glass` / `Blaze`×`Asciify` / `Glitch`×`Magnify` / `Clouds`×`RetroDither`）を
**トグルで 1 つずつ切り替え**て表示する。同時マウントは常に 1 組（= 2 コンテキスト）に抑える。

### 4-3. Object × Wrapper（P3）— 検証 T-3 の結果次第
```tsx
<Ripple><GlassObject src="/svg/logo.svg" /></Ripple>
```
**成立すれば目玉**。不成立なら並置（P4）に差し替える。
→ **必須要件にはせず、T-3 の後に採否を決める。**

### 4-4. 避けるべき例の展示
「`Shatter`×`Grid`」「`Glass`×`Magnify`」を**あえて壊れた例として見せる**。
研究がテーマの LP なので、失敗例は正当なコンテンツになる。

## 5. 実装順序（実装フェーズに入ったら）

```
1. 検証ページ（T-6 → T-1 → T-3 → T-2）      ← LP 本体より先
2. マウント予算管理の <Section> ラッパー      ← コア部品
3. カラートークン + RGB 0-1 変換ヘルパー
4. [01] バナー / [06] 制約 セクション        ← エフェクト不要、先に骨組みを固める
5. [03] カタログ 25 枚                       ← 量が多い。ここが本体
6. [00] Hero / [02] 解説
7. [04] ラボ                                 ← 検証結果を反映
8. [05] マトリクス / [07] 導入 / [08] Footer
9. 非対応ブラウザ・reduced-motion の通し確認（T-8 / T-9）
```

**1 と 2 を飛ばすと、25 セクションを作った後にコンテキストロストで作り直しになる。**
